Common use cases: embedding a snapshot viewer next to a robot's data, rendering test fixtures in a custom dashboard, or shipping the visualizer in a larger debugging surface.

## Getting started

### Prerequisites

A Svelte 5 / SvelteKit (or Astro+Svelte, Vite+Svelte, etc.) project. The package is `svelte`-typed and built for runes; you cannot consume it from Svelte 4.

### Install

```bash
pnpm add @viamrobotics/visualization
```

The package declares a list of `peerDependencies` (Svelte, Threlte, Three.js, the Viam SDK, prime-core, several Zag.js components, etc.). pnpm will print warnings for any that aren't already in your project — install whatever it asks for.

Peers that only a plugin needs are marked optional, so you install them only if you mount that plugin: `@viamrobotics/sdk` and `@viamrobotics/svelte-sdk` for [`<Machine />`](../../plugins/machine/) and the plugins that need a machine, `@viamrobotics/test-widgets` for [`<ControlWidgets />`](../../plugins/control-widgets/), `@dimforge/rapier3d-compat`, `@threlte/rapier`, and `@viamrobotics/prime-editor` for `MoveFrame`, `@zag-js/tree-view` and `svelte-virtuallists` for [`<WorldTree />`](../../plugins/world-tree/), `@zag-js/tabs` for [`<Settings />`](../../plugins/settings/), `@threlte/xr` for [`<XR />`](../../plugins/xr/), `earcut` for [`<SelectionTool />`](../../plugins/selection/), and the Connect RPC client for [`<DrawService />`](../../plugins/draw-service/).

<Aside
	type="tip"
	title="Auto-install peers"
>
	If you don't want to chase peer warnings one at a time, set `auto-install-peers=true` in your
	`.npmrc`, or pass `--strict-peer-dependencies=false` on install.
</Aside>

### Configure your bundler

three is a peer of both your app and the visualizer. Resolve it from one place, so a second copy
can't slip in.

```ts
// vite.config.ts
import { defineConfig } from 'vite'

export default defineConfig({
	resolve: {
		// three is a peer of both your app and the visualizer; resolve it from one place
		// so a second copy can't slip in. Two three instances break `instanceof`.
		dedupe: ['three'],
	},
})
```

### Set up styles

The visualizer is styled with Tailwind 4 and the Viam prime design system, so your app needs
Tailwind 4. Tailwind does not scan `node_modules`, so each package ships a stylesheet that
points Tailwind at its own components. Import them in this order, after Tailwind:

```css
/* app.css */
@import 'tailwindcss';
@import '@viamrobotics/prime-ui/styles.css';
@import '@viamrobotics/prime-controls/styles.css';
@import '@viamrobotics/visualization/styles.css';
```

If your app already uses prime-ui and prime-controls, add only the last line. Importing a prime
stylesheet a second time duplicates its rules.

`<MoveFrame />` also needs `@import '@viamrobotics/prime-editor/styles.css'`
for its JSON editor.

The visualizer's panels use the prime fonts. Load them once, from your app's entry:

```ts
import '@viamrobotics/tailwind-config/fonts'
```

### Disable SSR for the page

The visualizer renders with WebGPU (falling back to WebGL2), which needs the browser. Disable SSR on any page that mounts `<Visualizer />`. In SvelteKit:

```ts
// src/routes/visualizer/+page.ts
export const ssr = false
```

<Aside
	type="tip"
	title="Astro"
>
	In Astro, add `client:only="svelte"` to the component tag instead.
</Aside>

## Mounting `<Visualizer />`

`<Visualizer />` is the entire visualizer rendered as a single Svelte component. It expects an explicitly-sized parent because it stretches to fill its container:

```svelte
<script lang="ts">
	import { Visualizer } from '@viamrobotics/visualization'
</script>

<div class="h-screen w-screen">
	<Visualizer />
</div>
```

That's enough to get an empty scene: the camera and its controls, the grid, the entity
renderer, and the portal targets plugins render into. From there, you can:

- **Mount [`<Machine partID />`](../../plugins/machine/)** inside it to render a Viam machine part, with the plugins that work on the machine as its children.
- **Pass `cameraPose`** to set an initial camera position and look-at target.
- **Provide a `children` snippet** to render your own Threlte primitives or the `<Snapshot />` component inside the scene.

## What's in the box, and what isn't

`<Visualizer />` is the scene, not the app. It renders:

- the `<Canvas>`, in `renderMode="on-demand"`
- the camera, camera controls, and the reset / orthographic buttons
- the grid, lighting, and environment
- the entity renderer — everything spawned into the ECS world, including `<PCD />`
- selection and hover affordances
- the portal targets that plugins render their UI into

It also shows a details panel for whatever you select. Everything else is a plugin you opt into — including the workspace modes: with no mode plugin mounted the mode is `none`, with no toggle and no live-query pausing. The visualizer's own chrome ships as plugins:

| Plugin                                           | Adds                                             |
| ------------------------------------------------ | ------------------------------------------------ |
| [`<Machine />`](../../plugins/machine/)          | A machine part, and monitor mode for watching it |
| [`<WorldTree />`](../../plugins/world-tree/)     | The scene hierarchy panel                        |
| [`<Settings />`](../../plugins/settings/)        | The settings cog and its tabbed popover          |
| [`<BuildFrames />`](../../plugins/build-frames/) | Build mode: gizmos, snapping, frame editing      |
| [`<FileDrop />`](../../plugins/file-drop/)       | Drag-and-drop loading of snapshots, PCD and PLY  |

To reproduce the standalone app, mount all of these plus the feature plugins you want, keeping
`BuildFrames` before `MoveFrame` inside `Machine`. Monitor mode comes first because `Machine`
registers it, and mode plugins' mount order sets both the toggle's button order and the fallback
priority. To embed a focused viewer, mount none of them —
or just the one or two that earn their space.

### Importing plugins

Each plugin has its own subpath, named after the component in kebab case:

```ts
import { Machine } from '@viamrobotics/visualization/plugins/machine'
import { MeasureTool } from '@viamrobotics/visualization/plugins/measure-tool'
```

Import from these subpaths. Each one loads only its own plugin, so you install only the optional
peers for the plugins you mount. The `@viamrobotics/visualization/plugins` barrel still exports
every plugin, but it loads all of them, so it needs every optional peer installed. See
[Plugin dependencies](../../plugins/dependencies/) for which plugin needs which peer.

<Aside
	type="caution"
	title="Chrome that reaches past the visualizer"
>
	FileDrop listens for drags on the window, so it intercepts drops meant for the host app — leave it
	out of embedded viewers. Keyboard shortcuts are also window-level, but only the bindings your
	mounted features contribute exist at all (a bare visualizer binds just `c` and `h`); pass
	`inputBindingsEnabled={false}` to silence keyboard input entirely.
</Aside>

## A focused point-cloud viewer

The smallest useful embed: a scene, a point cloud you already have the bytes for, and a ruler.
`<PCD />` parses in a worker and spawns an entity the visualizer's renderer picks up, so nothing
else is needed — no `partID`, and no network calls of its own.

```svelte
<script lang="ts">
	import { PCD, Visualizer } from '@viamrobotics/visualization'
	import { MeasureTool } from '@viamrobotics/visualization/plugins/measure-tool'

	interface Props {
		data: Uint8Array
	}

	let { data }: Props = $props()
</script>

<div class="h-120 w-full">
	<Visualizer>
		<PCD {data} />
		<MeasureTool />
	</Visualizer>
</div>
```

Rebinding `data` reparses and respawns the entity, so this works for a polling feed as well as a
one-shot capture.

<Aside
	type="note"
	title="Point size lives in settings"
>
	Point size comes from `useSettings().current.pointSize` (in metres), which the [Settings
	plugin](../../plugins/settings/) normally edits. To expose one control without the whole popover,
	write that field from your own plugin — and call `invalidate()` from `useThrelte()` afterward,
	because the canvas only repaints on demand and the settings popover is what usually triggers it.
	See [Authoring plugins](../../plugins/authoring/).
</Aside>

## Passing props and children

```svelte
<script lang="ts">
	import { Visualizer } from '@viamrobotics/visualization'
</script>

<div class="h-screen w-screen">
	<Visualizer cameraPose={{ position: [2, 2, 2], lookAt: [0, 0, 0] }}>
		{#snippet children()}
			<!-- Anything Threlte-compatible. Runs inside <Canvas>. -->
		{/snippet}
	</Visualizer>
</div>
```

## Remembering state across reloads

The visualizer keeps some state as you use it: settings, the workspace mode, the open details
tab, the orientation format, and what plugins keep, such as `<WorldTree />` folder expansion and
open control widgets. Each `<Visualizer>` keeps its own, and every component inside one visualizer
shares it.

By default that state lives in memory, so it is gone on reload, and storage is never read or
written. Pass `storageKey` to persist it in the host page's origin, under that prefix. It is read
once, on mount.

| Value    | Effect                                                                 |
| -------- | ---------------------------------------------------------------------- |
| omitted  | Keeps the state in memory, for this visualizer alone.                  |
| a string | Persists every value under that prefix, such as `arm-widget:settings`. |

```svelte
<Visualizer storageKey="arm-widget" />
```

Give each viewer that should remember its own state a different string. Visualizers given the same
string share their persisted state. The standalone app uses `visualizer`, so pick another string
unless an embedded viewer should share the app's state.

XR's `anchorKey` is not under `storageKey`. It names a calibration stored on the headset, which
every viewer on that device shares.

## Rendering snapshots

A **snapshot** is a serialized scene — every transform, drawing, and camera setting captured into one protobuf payload. Snapshots render purely client-side; no draw server, no live machine, no network calls.

Use the `<Snapshot />` component as a child of `<Visualizer />`:

<Tabs syncKey="snapshot-source">
  <TabItem label="From a static file">
    Put the snapshot in your app's `public/` (or `static/`) directory and fetch it at runtime. This is the pattern the <a href={`${import.meta.env.BASE_URL}playground/snapshot`}>playground</a> uses.

    ```svelte
    <script lang="ts">
      import { onMount } from 'svelte'
      import { Visualizer } from '@viamrobotics/visualization'
      import { Snapshot, SnapshotProto } from '@viamrobotics/visualization/lib'

      let snapshot = $state<SnapshotProto | undefined>()

      onMount(async () => {
        const response = await fetch('/scene.snapshot.pb')
        const buffer = await response.arrayBuffer()
        snapshot = SnapshotProto.fromBinary(new Uint8Array(buffer))
      })
    </script>

    <div class="h-screen w-screen">
      <Visualizer>
        {#if snapshot}
          <Snapshot {snapshot} />
        {/if}
      </Visualizer>
    </div>
    ```

  </TabItem>
  <TabItem label="From a URL">
    Fetch and decode at runtime:

    ```svelte
    <script lang="ts">
      import { onMount } from 'svelte'
      import { Visualizer } from '@viamrobotics/visualization'
      import { Snapshot, SnapshotProto } from '@viamrobotics/visualization/lib'

      let snapshot = $state<SnapshotProto | undefined>()

      onMount(async () => {
        const response = await fetch('/api/snapshots/latest.pb')
        const buffer = await response.arrayBuffer()
        snapshot = SnapshotProto.fromBinary(new Uint8Array(buffer))
      })
    </script>

    <div class="h-screen w-screen">
      <Visualizer>
        {#if snapshot}
          <Snapshot {snapshot} />
        {/if}
      </Visualizer>
    </div>
    ```

  </TabItem>
  <TabItem label="From JSON">
    JSON snapshots are bigger but easier to debug:

    ```svelte
    <script lang="ts">
      import { Visualizer } from '@viamrobotics/visualization'
      import { Snapshot, SnapshotProto } from '@viamrobotics/visualization/lib'
      import sceneJson from './scene.snapshot.json?raw'

      const snapshot = SnapshotProto.fromJsonString(sceneJson)
    </script>

    <div class="h-screen w-screen">
      <Visualizer>
        <Snapshot {snapshot} />
      </Visualizer>
    </div>
    ```

  </TabItem>
</Tabs>

You can re-bind a different snapshot at any time — `<Snapshot />` watches the prop and respawns the scene entities when the value changes.

The <a href={`${import.meta.env.BASE_URL}playground/snapshot`}>playground</a> renders this snapshot by default. To experiment with it, download <a href={`${import.meta.env.BASE_URL}playground/visualization_snapshot.json`}><code>visualization_snapshot.json</code></a>, edit a few values, and drag the modified file onto the playground — the scene re-renders with your changes. The drop zone accepts `.json`, `.pb`, and `.pb.gz` snapshot files, but they must be named with a `visualization_snapshot` prefix (see [src/lib/plugins/FileDrop/file-names.ts](https://github.com/viamrobotics/visualization/blob/main/src/lib/plugins/FileDrop/file-names.ts)) for the loader to recognize them.

## Producing snapshots

Snapshots are produced from Go using the [`draw` package](../../api/draw/). The most common pattern: build up a `*draw.Snapshot`, then call `MarshalBinary()` (or `MarshalJSON()` for human-readable output) and ship the bytes wherever your frontend can fetch them.

A minimal producer:

```go
package main

import (
    "os"

    "github.com/golang/geo/r3"
    "github.com/viamrobotics/visualization/draw"
    "go.viam.com/rdk/spatialmath"
)

func main() {
    snapshot := draw.NewSnapshot(
        draw.WithGrid(true),
        draw.WithSceneCamera(draw.NewSceneCamera(
            r3.Vector{X: 2000, Y: 2000, Z: 2000},
            r3.Vector{X: 0, Y: 0, Z: 0},
        )),
    )

    box, _ := spatialmath.NewBox(
        spatialmath.NewZeroPose(),
        r3.Vector{X: 100, Y: 100, Z: 100},
        "box",
    )
    _, _ = snapshot.DrawGeometry(draw.DrawGeometryOptions{
        Geometry: box,
        Pose:     spatialmath.NewZeroPose(),
        Parent:   "world",
        Color:    draw.ColorFromName("red"),
    })

    bytes, _ := snapshot.MarshalBinary()
    _ = os.WriteFile("scene.snapshot.pb", bytes, 0644)
}
```

See the [`draw` API reference](../../api/draw/) for the full set of `Snapshot.Draw*` methods.

## Using only the standalone components

A few components are exported via the `/lib` subpath and work without a `<Visualizer />` parent — useful if you just need a piece of the visualizer (e.g. an axes helper) inside your own Threlte canvas:

```svelte
<script lang="ts">
	import { Canvas } from '@threlte/core/webgpu'
	import { AxesHelper } from '@viamrobotics/visualization/lib'
</script>

<Canvas>
	<AxesHelper />
</Canvas>
```

The standalone components use node materials, so they render only inside a `WebGPURenderer`. Use the `Canvas` from `@threlte/core/webgpu`, not the one from `@threlte/core`.

`<Snapshot />` is also exported from `/lib`, but unlike `<AxesHelper />` it requires the context that `<Visualizer />` provides — use it as a child of `<Visualizer />`, not standalone.
