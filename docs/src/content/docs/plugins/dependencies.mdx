---
title: Plugin dependencies
description: How visualizer plugins depend on external packages, each other, and the runtime environment.
---

Every plugin mounts independently inside `<Visualizer />`, and none _requires_ another plugin to function. A few, though, rely on optional npm packages, a live machine connection, or coordinate with a sibling plugin at runtime. This page audits those relationships so you know what to install and mount together.

## External packages

Most plugins need nothing beyond `@viamrobotics/visualization`. Several use **optional peer dependencies** — install them only when you use the plugin:

| Plugin                | Install                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `<Machine />`         | `@viamrobotics/sdk @viamrobotics/svelte-sdk`                                                                      |
| `<Arm />`             | `@viamrobotics/sdk @viamrobotics/svelte-sdk`                                                                      |
| `<LLMSceneBuilder />` | `@viamrobotics/svelte-sdk`                                                                                        |
| `<BuildFrames />`     | `@viamrobotics/sdk @viamrobotics/svelte-sdk`                                                                      |
| `<TestWidgets />`     | `@viamrobotics/test-widgets @viamrobotics/svelte-sdk`                                                             |
| `<SelectionTool />`   | `earcut`                                                                                                          |
| `<SensorCoverage />`  | `@viamrobotics/svelte-sdk`                                                                                        |
| `<DrawService />`     | `@connectrpc/connect @connectrpc/connect-web`                                                                     |
| `<Debug />`           | `@tanstack/svelte-query-devtools`                                                                                 |
| `<MoveFrame />`       | `@dimforge/rapier3d-compat @threlte/rapier @viamrobotics/prime-editor @viamrobotics/sdk @viamrobotics/svelte-sdk` |
| `<WorldTree />`       | `@zag-js/tree-view svelte-virtuallists`                                                                           |
| `<XR />`              | `@threlte/xr @viamrobotics/sdk @viamrobotics/svelte-sdk`                                                          |

A peer stays optional only when you import each plugin from its own subpath, such as
`@viamrobotics/visualization/plugins/measure-tool`. The `@viamrobotics/visualization/plugins`
barrel loads every plugin, so importing anything from it needs every peer in this table.

## Plugin-to-plugin

No plugin imports another as a hard requirement, but several pairs coordinate at runtime. Each is **soft**: the dependent plugin still works alone, just with reduced behavior.

| Plugin                    | Coordinates with | What happens                                                                                                             |
| ------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `<TestWidgets />`         | `<XR />`         | Registry widget panels are hidden while an immersive XR session is active.                                               |
| `<DrawService />`         | `<Logs />`       | Connection status and errors are written to the Logs panel. Without Logs, they're dropped silently.                      |
| mode plugins              | each other       | Buttons portal into the mode toggle in mount order, which is also fallback priority. Machine's monitor mode comes first. |
| any `SettingsPortal` user | `<Settings />`   | The contributed tab is registered either way, but only renders when Settings is mounted.                                 |

```text
TestWidgets ──► XR            panels hide during an immersive session
DrawService ──► Logs          draw-server diagnostics, if Logs is mounted
Machine ──► BuildFrames ──► MoveFrame   mount order is button order and priority
SettingsPortal ──► Settings   contributed tabs need a popover to live in
```

The `<TestWidgets />` ──► `<XR />` link only observes the session state XR publishes to `useEnvironment().current.isImmersive`, not the other plugin's internals — which is what lets `@threlte/xr` stay an optional peer. Which cameras appear in a headset is chosen independently in the [`<XR />`](../xr/) plugin's own **AR** settings panel.

## Plugins

Plugins are the visualizer's own chrome, split out so an embedded viewer doesn't inherit UI it has no use for: [`<Machine />`](../machine/), [`<WorldTree />`](../world-tree/), [`<Settings />`](../settings/), [`<BuildFrames />`](../build-frames/), and [`<FileDrop />`](../file-drop/). Mount all of them, with BuildFrames inside Machine, for the full standalone app. Mount none for a bare scene with camera controls.

One of them reaches beyond the visualizer element: `<FileDrop />` listens for drags on `window`, so it swallows drag-and-drop for the whole page. Keyboard shortcuts are dispatched by core but exist only when the feature contributing them is mounted, and `inputBindingsEnabled={false}` disables keyboard input wholesale.

## Runtime requirements

Some plugins need more than a mounted `<Visualizer />`:

| Plugin                                                                                           | Also needs                                                                          |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `<TestWidgets />`, `<LLMSceneBuilder />`, `<MoveFrame />`, `<SensorCoverage />`, `<XRMachine />` | to be inside `<Machine />`                                                          |
| `<BuildFrames />`                                                                                | to be inside `<Machine />`, with edit permissions on its part                       |
| `<Arm />`                                                                                        | `<ViamProvider>` from `@viamrobotics/svelte-sdk`, with a dial config for its part   |
| `<XR />`                                                                                         | a WebXR-capable device to enter a session                                           |
| `<Isolate />`                                                                                    | an active selection. Click an entity first                                          |
| `<DrawService />`                                                                                | a running draw server (see its [page](../draw-service/))                            |
| `<TopDownLock />`                                                                                | orbit-style camera controls, the default. It has no effect under trackball controls |
