---
title: <XR />
description: View and teleoperate a machine in an immersive WebXR (AR/VR) session.
---

`<XR />` brings the visualizer into a headset. It adds an **AR** button that starts an immersive WebXR session (on a device such as a Meta Quest) and an **AR** settings panel for configuring it. Inside the session the scene is pinned to a real-world origin so the machine appears at a fixed spot in the room; depending on the mode you can teleoperate arms with the controllers or reposition frames in space, with optional floating camera feeds and joint-limit readouts.

A WebXR-capable device and browser are required — on a regular desktop browser the button is present but can't start a session.

## Usage

Mount `<XR />` inside `<Visualizer />` to view the scene in a headset:

```svelte
<script lang="ts">
	import { Visualizer } from '@viamrobotics/visualization'
	import { XR } from '@viamrobotics/visualization/plugins/xr'
</script>

<div class="h-screen w-screen">
	<Visualizer>
		<XR />
	</Visualizer>
</div>
```

For a machine, put `<XR />` inside [`<Machine />`](../machine/) and give it an `<XRMachine />` child. `<XRMachine />` adds the camera feeds, joint limits, arm teleop, frame configuration, and their settings. Give each part its own `anchorKey`, so each physical setup keeps its own calibrated origin:

```svelte
<script lang="ts">
	import { Visualizer } from '@viamrobotics/visualization'
	import { Machine } from '@viamrobotics/visualization/plugins/machine'
	import { XR, XRMachine } from '@viamrobotics/visualization/plugins/xr'

	const partID = 'my-part-id'
</script>

<div class="h-screen w-screen">
	<Visualizer>
		<Machine {partID}>
			<XR anchorKey="xr-origin-anchor:{partID}">
				<XRMachine />
			</XR>
		</Machine>
	</Visualizer>
</div>
```

## Enabling and configuring

`<XR />` adds an **AR** section to the visualizer's settings panel. Its **Enable VR / AR mode** switch turns on the session button.

With `<XRMachine />` mounted, the section also lets you:

1. **Choose cameras**: pick which of the machine's cameras appear as floating feeds in the headset.
2. **Assign arms and grippers** to the left and right controllers, and set per-controller motion **scale** and **rotation** behavior.

The active interaction mode determines what the controllers do in-session:

- **arm-teleop** — drive the assigned arms with the controllers.
- **frame-configure** — grab and reposition frames in the scene.

Put the headset on, open the machine's page, and tap **AR** to enter. Exiting the session resets the scene origin.

## Props

`<XR />` forwards any extra props to the underlying `@threlte/xr` `<XRButton />`, so you can pass through attributes to style or label the session button.

## Dependencies

- **External packages:** `@threlte/xr` and `@viamrobotics/svelte-sdk`, both optional peers. Install both to import from `@viamrobotics/visualization/plugins/xr`, even without a machine, because that entry point also exports `<XRMachine />`.
- **Plugins:** `<XRMachine />` goes inside both `<XR />` and [`<Machine />`](../machine/). Camera feeds, controller arm and gripper assignments, and other session options are configured in the **AR** settings panel. See [Plugin dependencies](../dependencies/).
- **Runtime:** a WebXR-capable device to enter a session. Teleoperation of the assigned arms and grippers also needs a live machine connection through `<Machine />`.
